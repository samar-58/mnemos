CONDITIONAL GO

Build the continuity engine, not another recorder.

The problem is real and now independently validated. The generic product—capture desktop activity, search it, expose it over MCP—is already crowded. The opening is reliable, explainable task memory that helps an agent resume work with minimal context.

What must change

Current framingSharper framing
Persistent computer memoryLocal, vendor-neutral task continuity for AI agents
Capture everythingCapture the minimum useful event set; expand only when evaluation proves a gap
Search historyReturn episodes, decisions, changes, blockers, and next steps with provenance
Any agent can access itEach agent gets an explicit capability grant, scoped by app, project, content type, and time
Memory as truthMemory as a confidence-scored inference the user can inspect, correct, or delete

Recommended product wedge

  1. Observe app switches, window/document titles, focused Accessibility elements, browser URLs where accessible, and idle boundaries.
  2. Group raw events into task episodes using time, app, document, repository, and semantic continuity.
  3. Extract only durable objects: goals, files touched, commands/outcomes, decisions, blockers, and unresolved next steps.
  4. Answer one high-value request: “Where did I leave off on this project?” with timestamps and links back to evidence.
  5. Expose that answer through permissioned MCP tools with strict token budgets and a query audit trail.

Non-negotiable features

Provenance

Every derived memory links to the events that produced it.

Privacy controls

Allow/deny apps and sites, pause, private-mode exclusion, retention, inspect, delete, and export.

Secret filtering

Suppress password fields, tokens, recovery phrases, and sensitive windows before persistence.

Untrusted-content boundary

Captured text is data, never agent instruction. Defend retrieval against prompt injection.

Agent permissions

Separate grants per client and per query, with visible access history.

Correction

Users can merge/split episodes and correct wrong conclusions.

Validation gates before a full build

  • Interview 5–10 developers who use at least two agents weekly; collect real examples of lost context.
  • At least 3 users install a rough prototype and leave it enabled for a week.
  • For 20 manually labeled task resumptions, the system identifies the correct project, last meaningful action, and next step at least 80% of the time.
  • Raw-to-retrieved context compression of at least 20× without losing the answer.
  • No known sensitive-field events persisted in a deliberate red-team test.
  • Background target: under 2% average CPU, under 250 MB steady-state memory, and under 100 MB/day for the event-only MVP.
